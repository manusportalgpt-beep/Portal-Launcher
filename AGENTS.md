# Portal Launcher — правила работы

## Что это

Tauri 2 (Rust) + React + TypeScript. Rust — вся логика лаунчера и логика Minecraft
(version.json, classpath, FML/NeoForge, CurseForge, Modrinth). Frontend — только UI.

## Проверка сборки

Локально **нельзя** собрать: нет Node.js (нет `tsc --noEmit`, нет `vite build`)
и нет Visual Studio/`link.exe` для Rust. Единственная проверка — GitHub Actions
в `.github/workflows/main.yml`, `npm run build` + `cargo build`.

`gh` в окружении агента может быть недоступен. Статус workflow читается публичным
API без авторизации:

```
https://api.github.com/repos/manusportalgpt-beep/Portal-Launcher/actions/runs?per_page=2
```

Логи джобов требуют авторизации. Не считать задачу выполненной, пока CI не зелёный
и пользователь не подтвердил поведение у себя.

## Правки существующего кода

- Никогда не переписывать большие TSX-файлы скриптами или PowerShell. Это уже
  несколько раз ломало строки, кавычки и скобки без внятной ошибки. Правки —
  редактором, небольшими блоками, с перечитыванием результата.
- Не менять структуру, роуты и страницы, если об этом не просят. Задача дизайна —
  компонент или токен, а не редизайн.
- `src/styles/uiverse.css` генерируется из `tools/build-uiverse-css.mjs`.
  Постоянные override-правила добавлять в сборщик, не в готовый CSS.
- Перед `git push`: `git fetch origin --prune`, затем
  `git rev-list --left-right --count origin/main...HEAD`. Никакого force-push.
  В remote есть коммиты не из этой сессии — их нельзя затирать.

## Дизайн

Свою дизайн-систему не вводить: в проекте уже есть токены и компоненты.

- Цвета, отступы, радиусы, границы — только через `var(--color-*)` и
  существующие классы. Не хардкодить hex в компонентах.
- Одна акцентная палитра на экран. Не плодить градиенты, свечения и тени ради
  декора.
- Никаких emoji в UI и в тексте.
- Иконки — из `lucide-react`, уже подключённой библиотеки. Не рисовать иконки
  инлайновым SVG, CSS-фигурами или символами.
- Не выдумывать фичи, чтобы заполнить пустоту, и не писать в UI длинные
  пояснения.
- Реальные ассеты. Если картинки нет — попросить пользователя сгенерировать,
  а не подставлять заглушку-обводку и не растягивать чужую картинку.
- Ассет подбирается под слот: сначала измерить слот, потом подгонять по размеру,
  кадрированию, палитре и плотности.
- Тёмная и светлая темы — обе. Проверять контраст чёрно-красного персонажа на
  тёмном фоне, а не только на светлом.
- Долговременные решения по дизайну фиксировать здесь.

## Анимация

Правила из `animate` (Emil Kowalski):

- Только `transform` и `opacity`. Никаких `width`/`height`/`margin`/`top`/`left`.
- Вход/выход — `ease-out` = `cubic-bezier(0.23, 1, 0.32, 1)`.
  Движение по экрану — `ease-in-out` = `cubic-bezier(0.77, 0, 0.175, 1)`.
- UI-анимации короче 300 мс: 150–250 мс.
- Не анимировать то, что открывают 100+ раз в день (горячие клавиши, палитра
  команд). Там мгновенное переключение состояния.
- Вход не `scale(0)`, а `scale(0.95)` + `opacity: 0`.
- Поповеры и меню — `transform-origin` в точке триггера, не `center`.
  Модалки центрируются.
- На элементах, срабатывающих часто, — `transition`, а не `keyframes`.
- `transition: all` не используется, свойства перечисляются явно.
- Каждая анимация едет вместе с `prefers-reduced-motion` и гейтом
  `@media (hover: hover) and (pointer: fine)`.

## Диагностика запуска

Отчёты classpath и полная команда запуска пишутся в
`<instance>/.minecraft/portal-logs/` только при `PORTAL_LAUNCH_DEBUG=1`.
`log::info!` из Tauri уходит в stderr и пользователю не виден — диагностику
писать в файл.
