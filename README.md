## Что это

Portal Launcher — не «ещё один лаунчер». Обычный лаунчер умеет скачать мод и поставить его в папку. Здесь встроен **OpenPortal** — агент, у которого есть инструменты для всего: он читает файлы сборки, ищет контент на Modrinth и CurseForge, устанавливает его прямо в нужную сборку, пишет шейдеры и моды, настраивает конфиги, собирает `.jar` и читает лог после краша.

Ключевая идея: агент **не выдумывает**. Перед тем как сослаться на класс мода или метод Minecraft, он проверяет, что такой класс реально лежит в `.jar`; перед тем как создать файл в шейдере — смотрит, какие папки есть в архиве.

| Проверка сборки перед запуском, разбор крашей | Импорт из Prism и Modrinth App | Установка в один клик из чата |

## Возможности

### 🎮 Сборки и версии

- **Все версии Minecraft** — от 1.7.10 до свежих снапшотов, включая 26.x
- **Четыре лоадера**: Fabric (1.14+), Forge (1.7.10+), Quilt (1.14+), NeoForge (1.20.1+)
- Снапшоты скрыты по умолчанию и включаются одним переключателем
- Изолированные инстансы со своими RAM, Java и аргументами запуска
- **Java Manager** — сам скачивает и подбирает Java 8 / 16 / 17 / 21 / 25
- Импорт сборок из **Modrinth App** (`.mrpack`) и **Prism Launcher** (`.zip`)
- Детект существующих сборок Prism, Modrinth и других лаунчеров
- Глобальные моды — общие для всех сборок
- Экспорт сборки в `.mrpack` и ZIP

### 🧠 OpenPortal — ИИ-агент

- **39 инструментов**, а не урезанный набор: работа с файлами, поиск по коду, чтение и запись, сборка `.jar`, декомпиляция чужого мода, запуск Python, HTTP-запросы, веб-поиск
- **Глубокое знание сборок** — агент видит список модов с версиями, конфиги, `options.txt`, активный шейдер и ресурс-пак до начала работы
- **Запрет выдумывания**: класс, метод, mixin или файл, которых агент не видел через `jar_list`, `decompile_jar` или `archive_list`, в коде не появляются
- **Добивает задачу до конца** — не оставляет «...остальное по аналогии» и не рапортует успех без проверки
- **Уровень усилия**: `Default` — модель сама выберет глубину рассуждений, либо Мин / Низ / Сред / Выс
- **Режимы работы**: Build — выполняет, Plan — только план
- **Мультимодальность** — картинки из чата и найденные агентом файлы уходят модели как изображения, а не как набор цифр
- **Выбор модели из коробки**: OpenCode Zen, OpenRouter, OpenAI, Anthropic, DeepSeek, Ollama, LM Studio, GitHub Copilot
- Уровень контекста берётся из API или из локальной таблицы, есть ручная настройка

### 🧩 Контент

- Modrinth и CurseForge с фильтрами по версии, лоадеру и типу
- Автоподбор версии под конкретную сборку — версия Minecraft и лоадер подставляются сами
- Установка мода, ресурс-пака, шейдера или модпака прямо из ответа агента
- **Сборка (модпак) ставится как новая сборка**, а не внутрь существующей — так же, как в «Обзоре»
- Проверка конфликтов модов, дубликатов и битых JSON-конфигов перед запуском
- Автообновление модов внутри сборки

### 🌍 Instances Share

- Публикация сборки по ссылке: файлы с хешами ищутся на Modrinth и CurseForge, поэтому **моды не заливаются на сервер заново** — в ссылку попадают только ссылки на каталоги
- Прогресс по фазам с процентами и таймером, предупреждение если сервер не отвечает

### 🎨 Интерфейс

- Тёмные и светлые темы, акцент выбирается отдельно
- Стили оформления: OreUI и альтернативные
- Фоновые видео и изображения
- Скины, 3D-редактор скинов, скриншоты
- Отдельные вкладки, Lan-релей для игры по сети, хоткеи
- Полностью на русском

### 🔐 Аккаунты

- Вход в Microsoft по коду подтверждения (Device Code Flow) — внутри лаунчера, без стороннего браузера
- Ely.by и офлайн-профили
- Проверка владения Minecraft, refresh-токены с длительным сроком

## Как работают обновления

Механизм полностью на GitHub Releases, без собственного сервера. Ниже — точный путь от нажатия кнопки до установки.

### 1. Откуда берётся версия

Приложение знает свою версию из `src-tauri/Cargo.toml` → `version = "1.0.3"` (на момент публикации этого README).

Кнопка **«Проверить обновления»** в *Настройки → Обновление* вызывает команду `check_for_update`, которая делает один запрос:

```
GET https://api.github.com/repos/manusportalgpt-beep/Portal-Launcher/releases/latest
```

Заголовки запроса:

| Заголовок | Значение | Зачем |
|-----------|----------|-------|
| `User-Agent` | `PortalLauncher/<версия> (+ссылка)` | **обязателен** — без него GitHub отвечает `403 Forbidden` |
| `Accept` | `application/vnd.github+json` | стабильная версия API |
| `X-GitHub-Api-Version` | `2022-11-28` | фиксирует поведение API |

### 2. Сравнение версий

Из ответа берётся `tag_name`, отбрасывается ведущая `v`, и версии сравниваются по компонентам: `1.0.10` новее, чем `1.0.9`. Если релиз не новее установленной версии — приложение показывает «Актуальная версия» и ничего не скачивает.

Разбор версии терпимый: понимаются `v1.2.3`, `1.2.3`, `Portal 1.2.3` и `release-1.2.3-beta`.

### 3. Поиск файла

В релизе ищется первый файл с расширением `.exe` — это установщик (NSIS/Tauri). Если `.exe` в релизе нет, карточка всё равно показывается, но без кнопки установки и со ссылкой на страницу релиза.

### 4. Скачивание и установка

1. `download_update` качает `.exe` в `%APPDATA%\PortalLauncher\updates\` и шлёт событие `update-download-progress` — в приложении видно процент и скорость.
2. `install_update` запускает скачанный установщик и закрывает текущий процесс.
3. Дальше работает обычный установщик Windows.

### 5. Если GitHub API недоступен

Если API отвечает ошибкой или лимит запросов исчерпан, приложение **не показывает страшную ошибку**: оно повторяет проверку через обычную страницу `https://github.com/.../releases/latest` (этот путь лимитом API не ограничен) и берёт версию из адреса редиректа. Пользователю показывается понятный текст — «лимит API исчерпан, попробуйте через несколько минут» вместо `403 Forbidden`.

### 6. Автоматическая проверка

Кроме ручной кнопки, лаунчер сам проверяет обновления раз в 15 минут и показывает всплывающее уведомление. От него можно отложить на 30 минут или отказаться — отказ запоминается для конкретной версии.

### ⚠️ Как выпустить релиз, чтобы обновление нашлось

1. Поднять `version` в `src-tauri/Cargo.toml` (например `1.0.3` → `1.0.4`).
2. Запушить изменения в `main` и дождаться зелёной галочки в Actions.
3. Скачать инсталлер из артефактов прогона (`portal-launcher-windows-exe`) — это обычный `.exe` из `bundle/nsis`.
4. Создать релиз на GitHub с тегом **`v1.0.4`** и приложить этот `.exe`.

> **Важно:** теги вроде `Тест`, `LAN` или `NeW` не содержат версии. Приложение их не поймёт и покажет «Актуальная версия», даже если релиз новый. Нужен тег вида `v1.0.4`.

Actions только собирает проект и отдаёт инсталлер артефактом — сам релиз публикуется вручную, так что номер версии в теге ты контролируешь сам.

## Сборка из исходников

### Требования

- **Node.js** 20+ и **pnpm**
- **Rust** stable
- **Tauri prerequisites** — Visual Studio Build Tools (компонент «Desktop development with C++») на Windows, `webkit2gtk` + `libayatana-appindicator` на Linux, Xcode CLT на macOS

### Команды

```bash
pnpm install

pnpm tauri dev      # запуск в режиме разработки
pnpm tauri build    # сборка релизной версии
```

Frontend отдельно:

```bash
pnpm build          # проверка типов + сборка интерфейса
```

### Структура

```
src/                     React-интерфейс (TypeScript)
  pages/                 страницы: библиотека, обзор, настройки, OpenPortal
  components/openportal/ интерфейс агента и его модальные окна
  lib/opencore/          ядро агента: инструменты, промпт, работа с моделями
  stores/                состояние (инстансы, OpenPortal, тема, настройки)

src-tauri/               бэкенд (Rust)
  src/mc/                установка версий, merge наследования, запуск игры
  src/commands/          команды Tauri: инстансы, моды, лаунчер, OpenPortal
  src-tauri/src/commands/instance_share.rs   публикация сборок
  src-tauri/src/commands/loader_installer.rs установка Fabric/Forge/Quilt/NeoForge
```
