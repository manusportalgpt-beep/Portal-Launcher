# Правила и чек-лист

Свод правил из установленных скиллов, требований пользователя и разбора собственных
ошибок. Перед правкой UI проходи этот список. Пункт, который нельзя выполнить,
озвучивается до начала работы, а не после.

Источники: `animate` (Emil Kowalski), `gpt-taste`, `kill-ai-slop`, `ui-ux-pro-max`,
`design-system`, `frontend-design`, `product-design`, требования пользователя.

---

## 1. Иконки

- [ ] Иконки только из lucide: <https://lucide.dev/icons/>.
- [ ] Пути не по памяти. Перед использованием сверить с исходником:
      `https://unpkg.com/lucide-static@latest/icons/<name>.svg`
- [ ] Проверить, что имя иконки существует в lucide. Нет такой — искать похожую,
      а не рисовать свою.
- [ ] Одна библиотека на весь проект. В лаунчере это уже `lucide-react`.
- [ ] Собственные SVG, CSS-фигуры, символы Unicode и emoji как иконки запрещены.
- [ ] Один размер и одна толщина обводки на весь ряд иконок.

## 2. Существующие материалы

- [ ] Если панель, блок, экран или компонент уже есть — дорабатывать его, а не
      создавать второй рядом.
- [ ] Схлопывание панели: выезжает та же самая панель, а не новый оверлей с
      продублированным содержимым.
- [ ] Дублировать разметку ради второго состояния запрещено. Подписи, которые
      появляются при раскрытии, живут внутри тех же элементов и просто
      проявляются.
- [ ] Новую дизайн-систему не вводить. Токены, компоненты и паттерны лаунчера уже
      есть.
- [ ] Файлы, которые пользователь прислал, — основа. Не перерисовывать, не
      генерировать свои вместо них.

## 3. Выделение и состояния

- [ ] Выделение обязано быть цветным. Акцентный токен, а не только серый фон и
      вес шрифта.
- [ ] Активный, hover, focus, selected, disabled, loading, error — у каждого
      есть явный вид. Ни одно состояние не «просто такое же».
- [ ] Выделение читается на светлой и на тёмной теме.
- [ ] Focus-visible обязателен, убирать outline нельзя.

## 4. Объём работы

- [ ] Делать ровно то, что попросили. Соседние экраны, «улучшения», бонусные
      фичи, переработка того, о чём не просили, — не делать.
- [ ] Если задача распадается на части, спросить, какую делать первой.
- [ ] Не расширять объём без запроса, даже если идея выглядит хорошей. Идею
      можно предложить, но не реализовать молча.

## 5. Детализация

Минимум по каждому экрану и компоненту:

- [ ] Пустое состояние: что пусто, почему и что сделать дальше.
- [ ] Загрузка: скелетон или индикатор, не «пустая таблица».
- [ ] Ошибка: читаемый текст и действие для повтора.
- [ ] Hover, focus, active, disabled у каждого интерактивного элемента.
- [ ] Длинные значения: обрезка, перенос, подсказка — не молчаливый вылет за
      границу.
- [ ] Нулевые, отрицательные, очень большие значения.
- [ ] Обе темы, узкий экран, длинный текст интерфейса.
- [ ] Клавиатура: всё доступно с клавиатуры, порядок обхода осмысленный.
- [ ] Реальные данные того вида, что встретит пользователь. Не «Lorem» и не
      выдуманные метрики ради заполнения.

## 6. Производительность

Лагание почти всегда означает пересчёт раскладки, а не кривую анимацию.

- [ ] Никаких `innerHTML` и пересоздания узлов в тикере или таймере.
      Обновлять только `textContent` и `style` по заранее построенным узлам.
- [ ] Не читать раскладку в цикле анимации. `offsetWidth`, `getBoundingClientRect`,
      `scrollHeight` в кадре — табуретка для главного потока.
- [ ] Перезапуск CSS-перехода через reflow запрещён. Нужен откат цвета —
      Web Animations API или отдельный класс с продублированной анимацией.
- [ ] Анимировать `transform` и `opacity`. Не `width`, `height`, `top`, `left`,
      `margin`, `padding`.
- [ ] Глубина, полосы прогресса, акцент сегмента — `transform: scaleX()`, а не
      изменение размера.
- [ ] Все записи DOM за кадр собирать в одном `requestAnimationFrame`.
- [ ] `contain: layout paint` на независимых панелях.
- [ ] `will-change` — только на элементе, который действительно анимируется, и
      не на всём подряд.
- [ ] Числа с `font-variant-numeric: tabular-nums`, иначе колонка прыгает.

## 7. Анимация

Из `animate`:

- [ ] Сначала гейт по частоте. Что открывают 100+ раз в день — без анимации
      вообще: горячие клавиши, палитра команд, тумблеры.
- [ ] Назвать цель: отклик, согласованность пространства, индикация состояния,
      сглаживание скачка, объяснение. Не назвал — не анимируешь.
- [ ] Данные, которые читают, не двигаются ради красоты.
- [ ] Вход и выход — `cubic-bezier(0.23, 1, 0.32, 1)`.
- [ ] Движение по экрану — `cubic-bezier(0.77, 0, 0.175, 1)`.
- [ ] UI-анимация короче 300 мс, обычно 150–250.
- [ ] Вход не `scale(0)`, а `scale(0.95)` + `opacity: 0`.
- [ ] У поповеров и меню `transform-origin` в точке триггера. Модалки по центру.
- [ ] Выход симметричен входу.
- [ ] Часто срабатывающее — `transition`, не `keyframes`.
- [ ] `transition: all` запрещён, свойства перечисляются.
- [ ] `prefers-reduced-motion` едет вместе с анимацией: движение убирается,
      переходы, помогающие понять, что произошло, остаются.
- [ ] Hover только под `@media (hover: hover) and (pointer: fine)`.
- [ ] Список на 300 мс — шаг 30–80 мс, а не всё сразу.

## 8. Визуальный язык

Из `kill-ai-slop`:

- [ ] Нет индиго-фиолетовых градиентов, стекла, свечений, градиентного текста.
- [ ] Нет пилюль-спама и бейджей ради бейджей.
- [ ] Нет цветной полосы слева у выноски.
- [ ] Нет «SECTION 01», «QUESTION 05» и прочих мета-лейблов.
- [ ] Нет emoji в интерфейсе и в тексте.
- [ ] Нет текста-кнопки цвета фона: заливка подбирается под текст по контрасту.
- [ ] Радиусы умеренные и одинаковые. Тени — только у поверхностей над
      содержимым.
- [ ] Иерархия размеров настоящая, а не шесть вариантов одного кегля.
- [ ] Один акцент на экран.

## 9. Типографика и сетка

- [ ] Один шрифт на весь интерфейс плюс один моноширинный для чисел.
      В лаунчере — IBM Plex Sans и IBM Plex Mono, не дефолтный системный и не
      Inter/Space Grotesk.
- [ ] Шкала размеров небольшая и осмысленная.
- [ ] Заголовки без переносов в 6 строк, узкие колонки для заголовков
      запрещены.
- [ ] Сетка без декоративных пустот и случайных бенто-пробелов.
- [ ] Отступы из шкалы, не «на глаз».

## 10. Токены

- [ ] Цвет, радиусы, отступы, границы, тайминги — только токены
      `var(--color-*)` и подобные. Hex в компоненте запрещён.
- [ ] Тёмная и светлая темы задаются значениями токенов, а не форком вёрстки.
- [ ] Семантические токены, не буквальные: не «серый-500», а «второстепенный
      текст».
- [ ] Проверять контраст текста к фону в обеих темах.

## 11. Правка существующего кода

Из `product-design`:

- [ ] Сначала прочитать код и посмотреть работающее приложение.
- [ ] Следовать локальному `AGENTS.md` и этому файлу.
- [ ] Переиспользовать существующие компоненты и раскладки.
- [ ] Не менять структуру, роуты и страницы без запроса.
- [ ] Не выдумывать фичи для заполнения пустоты.
- [ ] Не писать в интерфейсе длинные пояснения.
- [ ] Решения, которые должны влиять на будущие правки, записывать сюда.

## 12. Код лаунчера

- [ ] Локально не собирается: нет Node и нет Visual Studio. Проверка — CI.
- [ ] Перед `git push`: `git fetch origin --prune` и
      `git rev-list --left-right --count origin/main...HEAD`.
- [ ] Force-push запрещён. Коммиты в remote не из этой сессии не трогаются.
- [ ] Большие TSX-файлы не переписываются скриптами и PowerShell.
- [ ] `src/styles/uiverse.css` генерируется. Правила — в
      `tools/build-uiverse-css.mjs`.
- [ ] Не считать задачу выполненной, пока CI не зелёный и пользователь не
      подтвердил поведение.
- [ ] Диагностика запуска — в файлы по `PORTAL_LAUNCH_DEBUG=1`, потому что
      `log::info!` из Tauri не виден пользователю.

## 13. Проверка перед сдачей

- [ ] Каждое состояние из пункта 5 реально открыто и осмотрено.
- [ ] Обе темы.
- [ ] Узкий экран.
- [ ] Клавиатура.
- [ ] Тяжёлое обновление данных — без лагов, без перестроения DOM.
- [ ] Сравнение с референсом в одном кадре, если референс есть.
- [ ] Цифры, сказанные пользователю, перепроверены дважды.

## Разбор собственных ошибок

### 1. Иконки по памяти

Отрисовал 14 иконок lucide по памяти. Сверил с исходником — 6 из 14 были
неправильные: `trending-up`, `layers`, `book-open`, `sliders-horizontal`, `moon`,
`search`. Пользователь увидел это сразу.

**Правило:** пути иконок только сверять с `lucide.dev/icons` или
`unpkg.com/lucide-static`, никогда не по памяти. Пункт 1.

### 2. Вместо существующей панели сделал вторую

Сайдбар схлопнул в иконки и выезжал оверлей с продублированными подписями,
брендом и разделителями. Пользователь просил, чтобы выезжала уже существующая
панель.

**Правило:** дублировать разметку ради второго состояния нельзя. Подписи живут
внутри тех же элементов и проявляются. Пункт 2.

### 3. Не менял цвет выделения

Активный пункт навигации был серым. Просили акцентный.

**Правило:** выделение цветное, через акцентный токен. Пункт 3.

### 4. Сделал лишнего

Семь страниц, выдуманные маржа и фьючерсы, кольцевая диаграмма, API-ключи.
Из этого просили две страницы и сайдбар.

**Правило:** ровно запрошенное. Пункт 4.

### 5. Мало деталей

Экраны выглядели пустыми: нет состояний загрузки, ошибки, пустого списка,
состояний кнопок.

**Правило:** минимум по деталям зафиксирован в пункте 5.

### 6. Не учился на ошибках

Одни и те же промахи повторялись между сессиями.

**Правило:** этот файл. Ошибка, найденная пользователем, попадает сюда с
формулировкой правила.

### 7. Лагание из-за кода, а не из-за кривой

В тикере каждую секунду перестраивался весь стакан через `innerHTML`, глубина
анимировалась через `width`, а перезапуск подсветки делался через
`void offsetWidth` — принудительный reflow на десятках ячеек.

**Правило:** пункт 6 целиком.

### 8. Subgrid развёл подписи и иконки

Рельс на `subgrid`, оверлей с фиксированными высотами. Подписи гарантированно
разъехались с иконками.

**Правило:** если ряд и его зеркало должны совпадать, у них обязаны быть
одинаковые явные размеры. Совпадающие структуры строятся на общих числах, а не
на наследовании треков.

### 9. Неверно прочитал собственные измерения

На карте ASCII увидел `+` и решил, что это пустота, объявил свои же замеры
ошибочными. Точные замеры были верны.

**Правило:** не пересматривать собственные числа по одному косому взгляду.
Перепроверка другим инструментом — это хорошо, вывод по нему — нет.

### 10. Придумывал секции настроек

Три колонки переключателей, которых никто не просил.

**Правило:** пункт 4. Настройки появляются, когда их просят.
